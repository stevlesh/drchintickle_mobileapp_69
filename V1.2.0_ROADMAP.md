## 📋 **Planned Features & Improvements**

### **1. Authentication Flow Overhaul** 🔐

#### **1.1 Fitbod-Style Two-Button Entry Flow**
**Priority:** High
**Effort:** Medium (2-3 hours)

**Current State:**
- Combined sign-up/sign-in screen
- "Sign Up" and "Sign In" tabs
- Not immediately clear which action new users should take

**Proposed Change:**
- New initial screen with two prominent buttons:
  - **"START TRAINING"** or **"GET JACKED"** (sign-up flow)
  - **"I'M BACK, BABY"** or **"RESUME GAINS"** (login flow)
- Use animated workout button style (current NeonBarButton or similar)
- Separate screens for sign-up vs login
- Dr. ChinTickle-style verbiage (silly, motivational, Miami Vice aesthetic)

**Benefits:**
- Clearer user intent
- Better conversion rates
- More personality in the auth flow
- Matches successful patterns from apps like Fitbod

---

#### **1.2 Auto-Login After Email Confirmation**
**Priority:** High
**Effort:** Medium (1-2 hours)

**Current State:**
- User signs up → checks email → clicks confirmation link
- App opens but user is NOT logged in
- User must manually click "Sign In" and enter credentials again
- Confusing UX ("I just confirmed... why am I not logged in?")

**Proposed Change:**
- Handle deep link authentication tokens properly
- Add deep link event listener in `App.js` or `LoginScreen.js`
- Extract auth tokens from confirmation URL
- Auto-sign in user after email confirmation
- Navigate directly to onboarding (skip manual login step)

**Technical Requirements:**
- Deep link handling for `drchintickle://auth/callback?token=...`
- Token extraction and Supabase session creation
- Error handling for expired/invalid tokens
- Proper navigation flow (onboarding vs dashboard)

**Benefits:**
- Seamless signup experience
- Reduces friction for new users
- Industry-standard behavior

### **2. Workout Experience Enhancements** 💪

#### **2.1 Rest Timer End Notifications**
**Priority:** High
**Effort:** Medium (2-3 hours)

**Current State:**
- Rest timer counts down in app
- No notification when rest period ends
- Users must keep app open and watch timer
- Easy to miss rest completion if multitasking

**Proposed Change:**
- Local push notification when rest timer reaches 0:00
- Notification title: "REST'S OVER, BABY! 💪"
- Notification body: "Time for set [X] of 8. Let's go!"
- Sound + vibration
- Tapping notification opens app to workout screen

**Technical Requirements:**
- Request notification permissions on first workout
- Use `expo-notifications` (already in dependencies?)
- Schedule notification when rest timer starts
- Cancel notification if user manually ends rest early
- Handle background/foreground states properly

**⚠️ CRITICAL: Lessons from October 2025 Production Build Crashes**

**What Happened:**
- Builds 2-9 all crashed on TestFlight (but dev builds worked fine)
- Initially suspected notifications (@notifee) - WRONG
- Actually caused by **missing EAS Secrets** for Supabase env vars
- Fix: Added EAS Secrets → Build 10 worked perfectly

**For v1.2.0 Notifications:**
- ✅ EAS Secrets already configured (builds 10-11 work)
- ✅ Use `expo-notifications` (well-supported, no custom native code)
- ✅ Already have `NSUserNotificationUsageDescription` in Info.plist
- ⚠️ Test on TestFlight before App Store submission
- ⚠️ Notifications are NOT the problem (October crash was env vars)

**Reference Documents:**
- `.claude/BUILD_CRASH_DIAGNOSIS_SUMMARY.md` - Full diagnosis
- `.claude/PRODUCTION_BUILD_TROUBLESHOOTING.md` - Quick reference

**Edge Cases:**
- User closes app during rest → notification still fires
- User manually advances to next set → cancel notification
- User backgrounds app → notification works
- iOS permission handling (already have `NSUserNotificationUsageDescription` in Info.plist)

**Benefits:**
- Better workout flow
- Users can multitask during rest (reply to texts, etc.)
- More professional app experience
- Keeps users engaged

#### **2.2 Server-Side Funny Workout Quotes (No More Lame Inspirational Ones)**
**Priority:** Medium
**Effort:** Medium-High (3-4 hours)

**Current State:**
- Quotes served client-side from `src/utils/quotes.js`
- Mix of genuinely funny quotes and generic inspirational ones
- No way to update quotes without app release
- Some quotes are cringey/lame

**Proposed Change:**
- Create `workout_quotes` table in Supabase
- Seed with only FUNNY, Dr. ChinTickle-brand quotes
- Create Edge Function: `get-quote` (returns random quote by context)
- Update client to fetch from server instead of local file
- Add admin interface (future) to add/remove/rate quotes

**Database Schema:**
```sql
CREATE TABLE workout_quotes (
  id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  text TEXT NOT NULL,
  context TEXT NOT NULL, -- 'preWorkout', 'rest', 'completion', 'dashboard'
  is_active BOOLEAN DEFAULT true,
  funny_rating INTEGER, -- 1-10, curated by you
  created_at TIMESTAMP DEFAULT NOW()
);

-- Index for fast random selection
CREATE INDEX idx_quotes_context_active ON workout_quotes(context, is_active);
```

**Quote Curation Guidelines:**
- ✅ Funny, self-aware, slightly absurd
- ✅ Dr. ChinTickle personality (Miami Vice, 69 pull-ups, beach vibes)
- ✅ References to the app's unique approach
- ❌ Generic motivational garbage ("You got this!" "Believe in yourself!")
- ❌ Toxic gym bro energy
- ❌ Anything that takes itself too seriously

**Example Funny Quotes:**
- "69 pull-ups? Nice." 🏖️
- "Your back is about to look like a bag of snakes. A sexy bag of snakes."
- "Remember: We're not bodybuilders. We're bodybuilders who can do 69 pull-ups."
- "Fun fact: 15 minutes of this beats 90 minutes of whatever the fitness influencers are selling."
- "The beach bodies aren't ready for your pull-up game."

**Edge Function:**
```typescript
// supabase/functions/get-quote/index.ts
// Returns random quote by context with client-side fallback
```

**Client Changes:**
- Update `getQuote()` in `quotes.js` to call Edge Function
- Keep local quotes as fallback (offline support)
- Add caching (don't fetch every time)

**Benefits:**
- Update quotes without app releases
- Better brand consistency
- Actually funny content (no more cringe)
- Can A/B test quotes server-side
- Community could suggest quotes (future)

### **3. Post-Approval Quick Wins** ✨

#### **3.1 Sign in with Apple** 🍎
**Priority:** High (required if re-adding Google OAuth)
**Effort:** Medium (2-3 hours)

**Why:**
- If you want to re-add Google OAuth, Apple requires Sign in with Apple
- Guideline 4.8 compliance
- Many users prefer Apple sign-in (privacy, convenience)

**Technical:**
- Add Apple Auth provider in Supabase
- Add "Sign in with Apple" button (required to be equal prominence to Google)
- Test on real device (doesn't work in simulator)

#### **3.2 Re-add Google OAuth (Optional)**
**Priority:** Low (not required)
**Effort:** Low (5 minutes - just uncomment)

**Note:**
- Can only re-add IF you also add Sign in with Apple
- Requires both buttons to have equal prominence
- May not be worth the complexity

---

#### **3.3 Account Deletion Grace Period (30 days)**
**Priority:** Low
**Effort:** Medium (2-3 hours)

**Why:**
- Industry best practice (accidental deletions)
- GDPR-friendly
- Better user trust

**How:**
- Soft-delete accounts (mark as `deleted_at` timestamp)
- Cron job to hard-delete after 30 days
- "Reactivate Account" flow if user logs in during grace period

---

#### **3.4 Data Export (GDPR Compliance)**
**Priority:** Low
**Effort:** Medium (2-3 hours)

**Why:**
- GDPR requirement (user data portability)
- Nice-to-have for power users
- Shows respect for user data

**How:**
- "Export My Data" button in settings
- Edge Function generates JSON/CSV with all user data
- Email download link or direct download
