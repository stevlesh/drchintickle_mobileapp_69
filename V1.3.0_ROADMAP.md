# 🚀 Dr. ChinTickle v1.3.0 Roadmap (Planning)

Status: Planning (post 1.2.0 submission)
Target: Next minor release focused on value, not patching

---

## 🎯 Primary Goals for v1.3.0
1) Rest timer end notifications (local notifications at rest completion)
2) Server-side funny quotes (replace local file, updateable without rebuilds)
3) Post-approval OTA task: write plan tuple with session insert (no binary)
4) Onboarding polish: fix iPhone 15 Pro width on screen 2; align colors with app

Out of scope: Password reset patch (defer to a future version if needed)

---

## 1) Rest Timer End Notifications
- Outcome: When a rest period hits 0:00, user receives a local notification (title + body + sound/vibration). Tapping the notification returns to the active workout screen.
- Approach: `expo-notifications` with permission request at first use of rest timer.
- Success criteria:
  - Notification reliably fires at 0 even if the app is backgrounded.
  - Tapping it focuses the app on the workout screen.
  - No double-fires or stale notifications if rest is skipped early.
  - Tested on real device via TestFlight.

---

## 2) Server-Side Quotes (Funny Only)
- Outcome: Quotes fetched from Supabase so content can change without a new binary.
- Approach:
  - Supabase table `workout_quotes(text, context, is_active, funny_rating, created_at)`
  - Edge Function `get-quote` that returns a random active quote for a given context.
  - Client calls Edge Function; falls back to local quote if offline.
- Success criteria:
  - API returns quotes in <200ms P50 from device.
  - Client shows quote even if offline (fallback).
  - Content updates are visible without app update.

---

## 3) Post-approval OTA Task (no App Store resubmission)
- Objective: Store exact plan info on each completed session.
- Code (JS-only; ship via `eas update` after approval):
  - File: `src/screens/WorkoutScreen.js` (handleFinishWorkout insert)
  - Add fields to insert payload:
    - `pattern: currentPlan?.pattern`
    - `cycle_num: currentPlan?.cycleNum`
    - `workout_num: currentPlan?.workoutNum`
  - QA checklist:
    - Complete a workout; confirm new row shows pattern/cycle/workout
    - View: `public.analytics_user_recent_workouts` lists correct pattern
  - EAS Update commands:
    - `eas update --branch preview --message "Write plan tuple on session"`
    - After QA: `eas update --branch production --message "Promote plan tuple write"`
- Rationale:
  - The UI already holds the exact plan; including it makes the session record self-contained and unambiguous.
  - Optional server trigger can fill if fields are missing.

## 4) Onboarding Polish (iPhone 15 Pro + Color Alignment)
- Outcome: On screen 2, metrics fit on iPhone 15 Pro (no overflow); onboarding colors match the main app palette.
- Approach:
  - Reduce metrics font sizes by 1–2 steps or tighten horizontal padding on second row.
  - Update background/gradients to match app primary palette.
- Success criteria:
  - Fits iPhone 15 Pro without truncation/overflow.
  - Visuals feel consistent with the app (no abrupt scheme shift).

## Add-on: Improve Stats Page (Last 12 Workouts)
- Outcome: Show each user a simple list of their last 12 workouts with date, workout type, completed reps, and duration.
- Data source: `public.analytics_recent_workouts` view (already created) filtered by `user_id = auth.uid()` and `LIMIT 12` in the client.
- Success criteria:
  - For a test user with 12+ sessions, list shows 12 rows sorted by most recent date.
  - Fields match `workout_sessions` values; duration uses `duration_minutes` or `duration_sec/60`.
