  const { data, error } = await supabase.auth.signUp({

    password: password

  console.log('Sign up response:', { data, error })

  if (error) {
    console.error('Sign up error:', error.message)
    if (error.message.includes('already registered')) {
      setFormError('This email is already registered. Try signing in.')
    } else {
      setFormError(error.message)
    }
    setSubmitted(false) // Allow retry on error
  } else {
    // SUCCESS - With email confirmation DISABLED:
    // User is immediately logged in!
    // App.js auth listener will detect session and route to Onboarding
    console.log('Signup successful, user logged in:', data.user.email)

    // Optional: Show brief success message before navigation
    setSuccessMessage('Account created! Logging you in...')
    // Navigation happens automatically via auth listener in App.js
  }

  setLoading(false)
}

```javascript
// In WelcomeScreen.js - useEffect on mount
// Remember to import: `import { resetTo } from '../navigation/navigationRef'`
useEffect(() => {
  const checkSession = async () => {
    const { data: { session } } = await supabase.auth.getSession();
    if (session) {
      // User already logged in, trigger global routing
      // This ensures onboarding check runs (not just going to Main)
      resetTo('Loading'); // NOT navigate('Main')
    }
  };
  checkSession();
}, []);
```

**WHY:** Prevents showing WelcomeScreen to already-logged-in users. If user backgrounds app on WelcomeScreen and later returns with active session, they should go through the full routing logic (`routeFromServerTruth()` in App.js) which checks onboarding status. Using `resetTo('Loading')` triggers this flow instead of forcing them to Main and potentially skipping onboarding.

**IMPORTANT:** Don't use `navigation.replace('Main')` because it bypasses the onboarding check. Always trigger the global routing flow.

## 🚨 ERROR HANDLING & EDGE CASES

### Error Scenarios to Handle

#### 1. **Network Errors**

**Scenario:** User has poor/no internet connection during signup/signin

**Handling:**
```javascript
try {
  const { data, error } = await supabase.auth.signUp(...)
  if (error) throw error
} catch (error) {
  if (error.message.includes('network') || error.message.includes('Failed to fetch')) {
    setFormError('Network error. Check your connection and try again.')
  } else {
    setFormError(error.message)
  }
}
```

**User sees:** "Network error. Check your connection and try again."

---

#### 2. **Duplicate Email (Signup)**

**Scenario:** User tries to sign up with email that already exists

**Handling:**
```javascript
if (error.message.includes('already registered') || error.message.includes('User already registered')) {
  setFormError('This email is already registered. Try signing in.')
}
```

**User sees:** "This email is already registered. Try signing in."

**UX Improvement:** Link could auto-navigate to SignInScreen with email pre-filled

---

#### 3. **Invalid Credentials (Signin)**

**Scenario:** User enters wrong email/password combo

**Handling:**
```javascript
if (error.message.includes('Invalid login credentials')) {
  setFormError('Invalid email or password')
}
```

**User sees:** "Invalid email or password"

**Security Note:** Don't reveal whether email exists (prevents email enumeration)

---

#### 4. **Weak Password**

**Scenario:** User enters password that doesn't meet Supabase requirements

**Handling:**
```javascript
if (error.message.includes('Password should be')) {
  setFormError('Password must be at least 6 characters')
}
```

**User sees:** "Password must be at least 6 characters"

**Note:** Client-side validation should catch this first (validatePassword)

---

#### 5. **Rate Limiting**

**Scenario:** Too many signup/signin attempts in short period

**Handling:**
```javascript
if (error.message.includes('rate limit') || error.message.includes('too many requests')) {
  setFormError('Too many attempts. Please try again in a few minutes.')
}
```

**User sees:** "Too many attempts. Please try again in a few minutes."

---

#### 6. **Email Format Invalid (Server-Side)**

**Scenario:** Client validation missed something, server rejects email

**Handling:**
```javascript
if (error.message.includes('invalid email') || error.message.includes('email format')) {
  setEmailError('Please enter a valid email address')
  setFormError('')
}
```

**User sees:** Error below email field

---

#### 7. **Password Reset Email Not Sent**

**Scenario:** Supabase fails to send password reset email

**Handling:**
```javascript
if (error) {
  setFormError('Failed to send reset email. Please try again.')
}
```

**User sees:** "Failed to send reset email. Please try again."

### 🚨 Critical Discovery: Deep Linking Completely Broken (Latest)

3. **No password reset completion UI** - Users can request reset, receive email, click link, but have nowhere to actually set new password

**Why This Is Critical:**
- Affects CURRENT app, not just new auth flow
- Users literally cannot reset their passwords right now
- Even if they could, there's no UI to complete the flow
- This is a production bug that needs fixing immediately

**How We Found It:**
- ChatGPT searched for `installAuthLinking` usage (found it's never called)
- Verified redirect URI in `redirect.js` vs `LoginScreen.js` (mismatch)
- Checked for password reset UI handling `PASSWORD_RECOVERY` event (none exists)

**Lesson:** Always verify that imported functions are actually called, and test critical flows end-to-end (not just "does it compile?").

### ⚠️ Navigation Routing Discovery (Earlier Finding)
**Found by:** ChatGPT + Claude analysis

**What We Missed Initially:**
1. **useGateMain.js** - Critical navigation guard that runs on Main tab focus. Would have sent users back to Login even after successful signup.
2. **App.js 2-second fallback** - Safety mechanism that kicks in if LoadingScreen gets stuck. Would have routed to Login instead of Welcome.
3. **OnboardingScreen.js pre-auth exit** - "How It Works" flow would have returned users to Login instead of Welcome.
4. **WelcomeScreen session check logic** - Using `navigate('Main')` would skip onboarding check.
5. **Scope of changes** - Initially thought 4-5 changes, actually 12 changes across 5 files (including WelcomeScreen).

### Best Practices Applied
1. ✅ **Comment out, don't delete** - Preserves code for future re-enabling
2. ✅ **Use `replace()` not `navigate()`** - Prevents navigation stack growth
3. ✅ **Add duplicate submission guards** - Prevents race conditions
4. ✅ **Systematic search** - Glob for all `resetTo('Login')` instances
5. ✅ **Check navigation hooks** - Don't just look at screens, check utility hooks

### Why This Plan Is Better Now

- **Tested:** Includes Phase 0 verification checklist
- **Realistic:** Timeline accounts for actual TestFlight processing times
